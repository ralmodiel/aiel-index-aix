# aiel-index (command: aix): a companion for Claude Code on big repos

## The problem
Working with Claude Code on a 1,300-file repo for one night (40+ UI rounds, ~15 builders, 8 reviewers), most tokens
went to the same lookups, over and over:
- Which page is behind this menu label, which roles see it, and which endpoints it calls with what permissions.
- Where a user-facing string lives, and which end-to-end test quotes it, so a rename doesn't break the suite.
- Whether something broke here before, and what fixed it.
- Whether a script for a given task already exists.
- What the current diff affects, and which tests and regression scripts cover it.
- Whether a claim in UI copy, like "the customer is notified", is true on the server.

Most bugs the reviewers caught were of the last kind: UI text that didn't match server behaviour. A grep-and-read loop
is expensive and easy to get wrong.

## What aix is
A local, always-fresh **project knowledge index** plus the workflow pieces that make Claude use it by default.

1. **Index (SQLite + FTS5 + optional embeddings), one file per repo in `.aix/index.db`.**
   - Facts are parsed deterministically, never generated by an LLM: files, symbols, routes, menus, endpoints with their
     auth, API clients, UI strings, tests, scripts, docs, task lists, and git history (fix/revert commits).
   - The knowledge layer covers the feature list, past bugs and QA findings, open decisions, and the "learnings" file.
   - Semantic search on top: a local embedder through any OpenAI-compatible `/v1/embeddings`, fused with bm25 (RRF). If
     the embedder is down it falls back to keywords only and never blocks.
   - Updates are incremental: blob hashes, git hooks, and a staleness check on every query.
2. **Canned queries that each return a whole answer in one bounded call.**
   - `brief <route|file>`: everything needed before editing (who sees it, what it calls, tests, past bugs, open decisions).
   - `impact`: what the current diff touches and which tests and strings it could break.
   - `bugs <area>`: the history of what went wrong here before.
   - `qa <area>`: how to test it.
   - `claims <file>`: user-facing promises in the copy ("notified", "cannot be undone", "only admins") paired with the
     server code that decides them, for a reviewer to verify.
   - `ask "<question>"` (hybrid semantic) and `find`, `text`, `endpoint`, `symbol`, `script`, `sql`.
3. **Claude Code integration.**
   - An MCP server (`aix` tool) and a skill that teaches when to use each query.
   - Hooks:
     - SessionStart injects a 10-line project card.
     - PreToolUse on broad `grep -r` / large Reads suggests the index query that answers it.
     - PostToolUse on Edit marks rows stale.
   - Slash commands: `/brief`, `/impact`, `/bugs`.
4. **Lead workflow kit, learned the hard way tonight.**
   - Patch-only builders in scratch copies, with a safe-apply script that filters out node_modules and dist.
   - A gate wrapper that greps one verdict line.
   - A reviewer prompt template focused on merge-blockers and claims-vs-server.
   - A TASKS.md convention (task / DECISION / Found) that the index reads back.
   - Disjoint file ownership per builder, with a conflict check before spawning.
5. **Savings meter.** It logs bytes returned per query against the estimated grep/read cost, so `aix stats`
   shows tokens saved per session.

## Extractors (pluggable)
- Interface: `detect(repo) -> bool` and `extract(changed) -> rows`.
- First set (from the prototype): React Router + TSX, JAX-RS/Quarkus, Playwright JSON specs, Markdown docs and
  QA findings, git history, shell/Python scripts, checklists.
- Next: Next.js, Express, Spring, Django/FastAPI, Rails, Go net/http, Jest/Vitest/pytest.

## Decisions (owner, 2026-10-22)
- Private for now.
- Rust: a single static binary `aix` (CLI + MCP server over stdio), no runtime to install.
  - `rusqlite` (bundled SQLite with FTS5) for the index. `tree-sitter` with TS/TSX, Java, Python, Bash, Go and
    Rust grammars for exact symbols, routes and strings (more accurate than the prototype's regexes).
  - `ignore` for gitignore-aware walking, `blake3` for change detection, `rayon` for parallel extraction.
  - `ureq` for the embedder, `clap` for the CLI, and `rmcp` (the official Rust MCP SDK) for the MCP server.
- Optional `numpy`-free cosine search in Rust (SIMD-friendly f32 dot products); vectors stored as BLOBs in the same DB.

## Charter (owner, 2026-10-22)
Claude Code has freedom to design and implement aix. Goal: save Claude tokens and speed up work on very large
projects, growing alongside the repos it indexes as they grow. Be generous with ideas; build the biggest
measured benefit first; take hints from what agents actually run and read (bench/script-usage.py,
bench/read-usage.py, bench/psql-usage.py over the local transcripts).
Never compromise users' security or privacy:
- local only (no network except the user's own embed/chat endpoints); read-only queries; nothing auto-approves tools
- secrets never indexed (secret files skipped, credential shapes redacted in every stored string); no auth tokens or
  passwords cached, ever; usage counters store script paths only, never command lines
- every change ships with tests + clippy, and anything claiming a saving is checked with bench/ab-bench.py
  (A/B: same tasks with vs without aix; ship only if cost/time/turns improve and correctness holds)
- overhead budget: hooks < 10 ms (PreToolUse) / < 100 ms (SessionStart, no rebuild); queries < 100 ms; card <= 15 lines

## Idea backlog (ranked by measured or estimated benefit; data from 347 transcripts since 2026-10-08)
Done 2026-10-22: refresh/watch scripts, two-command setup, hints (role gaps), table, code, symbol suggestions,
explicit "none" sections, impact fixes, menu keywords, script->endpoint links, secret redaction, script-run counter.
1. Shell/Read of big source files: 27.7 MB of output (top: a few large services and the shared API client). -> `code` (done); next: PreToolUse on a Read of a 600+ line file returns the outline
   with line ranges inline (no extra turn), and `brief file` lists methods with line ranges + one-line summaries.
2. Recursive grep (2,607 calls, 5 MB): make the PreToolUse nudge carry the answer (top 5 index hits, <= 600 chars)
   instead of a command to run; measure with ab-bench (risk: context added to greps that did not need it).
3. git log/show/diff (5 MB): `aix change <sha|rev>`: subject, files, touched symbols, linked tasks/findings,
   no patch text; `history` with per-commit touched symbols.
4. psql (3,100 calls): `table` (done); next `db` facts with TTL from a read-only script shipped in aix
   (database names, current period, counts per role: ids only, never emails, passwords or tokens).
5. API calls via curl (549): `endpoint` + request/response DTO fields from the Java records/classes, so agents
   build a correct request without reading the resource + DTO files.
6. "What to run": `aix verify` maps the diff to the minimal regress scripts + e2e scenarios + gate command.
7. Session card "since your last session": new commits, TASKS deltas, new findings (TASKS.md is read ~38 times).
8. Prefer the CLI in the skill (A/B: CLI -20% cost vs MCP -17%: no tool-loading turn); keep MCP optional.
9. Large-repo scale: incremental derive (not full), per-kind vector matrices cached in the MCP process, embed
   circuit breaker, immediate transactions + lock in Index::update, history dedupe (review findings 1-2, 4-5).
10. Playwright TS spec extractor and profile presets; `.aix/profile.toml` per repo.
11. `claims` query (copy promises vs server checks) + reviewer template; hints for "UI promise not enforced".

## Speed and token backlog (2026-10-24; from QA rounds and agent transcripts)
Goal: every agent question answered in one call, with the smallest correct answer, so agents never fall back to
grep/sed/Read. Evidence in brackets.

Requests (fewer retries and wrong turns):
1. Options anywhere: trailing `--limit/--max/--full/--count/--repo` are folded into the query on single-argument
   commands and give a false "none" with exit 0 [callers X --limit 3, tasks open --limit 3]. Parse flags in any position.
2. One flag vocabulary on every command and in MCP: `grep` refuses `--limit/--max/--full`; MCP `limit` is ignored for grep.
3. Paths: accept `./x`, `x\y`, `x//y`, a bare basename and paths relative to a subdirectory cwd on every command; say
   "path not found" instead of "0 matches" [outline ./a.tsx, grep x pages from a subdir].
4. `howto`: a curated task -> command table first ("list scripts" -> script, "file history" -> history, "who calls" ->
   callers, "read a whole file" -> code FILE --full), keyword ranking second.
5. `code <file> --max N` / `--full` on the plain file form (the cut-off line suggests it; only `file:A-B` works).
6. Exit codes: 0 found, 1 none, 2 error, on every command; MCP `isError` the same; usage errors never exit 0.
7. Disambiguation: `path::name` and `file:line` (done for callers/callees/impact) also for trace, explain and code.

Responses (fewer tokens per answer):
8. `scope` precision: a type-only or one-export change in a shared API client marks every page [103 of 110 routes for
   a one-field interface change; real impact 2]. Scope by the changed exports and their importers.
9. `trace`: drop the auth side-effect chain repeated on every endpoint (about half the rows) unless asked; collapse
   identical chains; follow calls into SQL functions so agents do not open migration files.
10. Findings: mark each doc/audit finding open or fixed (link a later fix commit or a code check), dedupe duplicates,
    hide fixed ones by default.
11. `find`: say when results are cut off (`20 of 319`) with the next command; fix `truncated:false` in `--jsonl`.
12. Outline footer suggests `code Class.method` [agents ran sed after outline]; code footer names `--max N` (done).
13. Session memory beyond `code`: a repeated brief/trace/outline in the same MCP session returns "unchanged since your
    last call (N lines)" or only the changed lines.
14. Per-command default `--skip`/`--fields` learned from usage (sections agents always skip), reported by `stats`.
15. Hook nudges that carry the answer (top hits, <= 600 chars) instead of a command (backlog item 2 above).
16. Role model: roles that see every page (super/support admins) and role-gap hints that read `hasAnyRole([...])`
    lists; every false hint costs a verification round [5 of 5 false on one page].
17. Menu/label locations: cite the menu definition file:line, not the page file [text "<menu label>"].

Speed:
18. (done) Incremental code graph: `cg:load` reloads the whole graph on every update (1.4 s at 60k files); cache it or load
    only the dirty names' neighbourhood. Incremental `derive` (0.9 s) and `walk` (0.4 s) at that size.
19. (done) MCP server: concurrent read queries (WAL readers) instead of one mutex, so parallel agents do not queue.
20. (done) `ask`: cache query embeddings; keep per-kind vector matrices in the MCP process; code-chunk embeddings for
    `--kind code` (done: hit@4 12/14 on strict ground truth; cold embed of a 1,300-file repo takes about 75 minutes).
21. First query after an edit: measure watcher-to-answer latency per stack; keep the no-op check under 20 ms.
22. Bounded worst cases: argument caps (done), regex budget (done), page clamps (done); add a per-command time budget
    that answers "partial, N of M" instead of running long.

Measurement:
23. Per-agent telemetry: aix calls vs grep/sed/Read fallbacks and tokens relayed per command (`stats --savings` per
    session), so each item above is judged by tokens saved, not by guesswork; A/B new defaults before shipping.

Accuracy gaps found while landing the above:
24. (done) UI strings: template literals in object-literal properties (`{ text: `${a} of ${b} learners need attention` }`)
    are not extracted, so `text` cannot find them even with live-value wildcards.
25. `ask --kind code` misses when the question's word differs from the code's ("OR number" vs `reference`): mine
    synonyms from the repo's own labels next to field names. (Tried: the repo has no label tying the question's words
    to the field, and `or` is a stopword; needs acronym-aware expansion, not a label rule.)

## Project focus (owner, 2026-10-22)
- Tailored to React + Java/Gradle web apps first, not a generic code graph (graphify, codebase-memory already cover calls/imports/paths).
- Encode the projects' own conventions as first-class facts: menu + synonym tables, @RolesAllowed vs menu roles
  (role-mismatch warnings), the api.ts chokepoint, e2e JSON specs and Playwright TS specs,
  regression scripts with header annotations, TASKS.md DECISION/Found, qa-findings rounds, deep-review outputs.
- Per-repo profile file (`.aix/profile.toml`, committed) for paths and conventions instead of hard-coding.
- Index updates only through `aix-refresh` (scripts shipped in this repo).
- Caching: SQLite in-process stays the store (queries 20-90 ms); hot data (decoded vectors, route/endpoint maps,
  embedder-down flag) is cached in memory by the long-lived MCP process. Redis only if a shared team server appears.

## Principles
- Local-first and private. No network except your own embedder.
- No daemon, one SQLite file per repo.
- Output is bounded by default (`--limit`, one line per hit); `--json` for tools.
- Deterministic facts first, semantic ranking second, LLM summaries optional and labelled.
